# Что нового

Изменения Zaslon по версиям.

## 1.4.3 — 24.11.2026

- В «Приложениях» появились Google Antigravity App и Google Antigravity IDE. Защиту каждого можно включить отдельно на Windows, macOS и Linux. Правила приложения распространяются и на его дочерние процессы, включая языковой сервер.
- В настройках обоих приложений указаны пять доменов Google для настройки маршрутов VPN. Эти домены используются для входа и запросов к API. Они не возвращают внешний IP при проверке Zaslon, поэтому по умолчанию защита Antigravity ориентируется на общий внешний IP.

## 1.4.2 — 21.11.2026

- Исправлена ошибка Windows, из-за которой Zaslon мог принять системные службы за дочерние процессы ChatGPT и попытаться их приостановить. Теперь Zaslon проверяет порядок запуска по номерам, которые выдаёт ядро Windows. Повторная выдача PID и перевод системных часов больше не путают родителя и потомка.
- Перед паузой Zaslon запрашивает у Windows статус процесса. Если процесс критический или Windows не даёт проверить его статус, Zaslon оставляет его работать.
- Если приложение успело завершиться до паузы, в журнале больше не появляется ложная запись о заморозке. При закрытии окна Zaslon также проверяет, что обращается к исходному экземпляру приложения.

## 1.4.1 — 19.11.2026

- На Linux защищённые консольные приложения снова принимают ввод после сетевой паузы. Где доступна cgroup v2 с правом создать отдельную группу для процесса, Zaslon сохраняет терминал за приложением даже при запуске по полному пути.
- Если cgroup недоступна, Zaslon сохраняет строгую паузу сигналами и пишет подсказку в журнал. В Bash команда `source <(zaslon bash-init)` включает автоматический возврат ввода для `codex` и `claude`. Другие консольные команды можно указать по имени.
- При перезапуске Zaslon восстанавливает подтверждённые паузы из журнала. На Ubuntu 24.04 проверены оба режима с Codex CLI, Claude Code и приложением с дочерними процессами. Повторные сбои IP-проверки сохраняли паузу, а после разрешённого ответа приложения снова реагировали на клавиши без `fg`.

## 1.4.0 — 19.11.2026

- На новой вкладке «Проверка» видно, какой IP и страну видит каждый сервис при соединении из Zaslon. Рядом с адресом показано, разрешён ли он правилами приложения. При тайм-ауте видно, какой домен не ответил. Кнопка «Проверить сейчас» обновляет измерения, сохраняя обычный режим защиты.
- Для каждого маршрута показаны текущее время ответа и среднее по успешным ответам среди последних пяти попыток. Если измерения есть только для IPv4, время занимает одну строку без префикса `v4`.
- По кнопке можно запросить у IPQuery сведения о выбранном адресе, включая провайдера, тип сети и отметки VPN, прокси и Tor. Ответ сохраняется локально и считается свежим семь дней. Отдельная проверка позволяет сравнить IPv4 с системным прокси и без него. Перед прямым запросом Zaslon просит подтверждение.
- Доверенные сети теперь находятся на одной вкладке с разрешёнными IP и странами. При добавлении сети Zaslon объясняет, когда приложения смогут работать без приостановки. В заголовках всех вкладок появились иконки для светлой и тёмной тем.
- Исправлено ложное срабатывание, при котором Zaslon мог попытаться приостановить посторонний процесс, например Диспетчер задач Windows. При определении дочерних процессов теперь учитывается время их запуска на случай, если система повторно выдала тот же PID.

## 1.3.5 — 18.11.2026

- В текстовом журнале видно, какое приложение поставлено на паузу и почему. Если один домен проверялся для нескольких приложений, запись о сбое перечисляет их вместе. При тайм-ауте полный URL больше не дублируется в тексте ошибки.
- «История» показывает, сколько времени приложение провело на паузе. Если его процессы остановились в разное время, виден диапазон. При смене причины паузы отсчёт продолжается.
- Одинаковые сбои в последовательных проверках собраны в одну запись со счётчиком. Нажмите строку со стрелкой справа, чтобы увидеть полный адрес, номера проверок и технические подробности. При обновлении списка строка остаётся раскрытой.

## 1.3.4 — 18.11.2026

### Защита

- Общий IP по умолчанию проверяется раз в минуту, а домены запущенных защищаемых приложений — каждые 15 секунд. Оба интервала можно менять отдельно. Если домен не ответил вовремя, Zaslon сразу повторяет запрос только к нему. В строгом режиме приложение ждёт подтверждения на паузе.
- Включение защиты одного приложения больше не прерывает работу остальных. После пробуждения Windows или длительного перерыва в обработке сетевых событий Zaslon заново проверяет соединение. Запоздалый ответ не снимает паузу.
- Если сервис уже сообщил запрещённый IP, последующий тайм-аут не отменяет запрет даже в режиме «Продолжать с предупреждением». При добавлении разрешения панель показывает точный адрес, подсеть или страну. Разрешение для IPv4 не расширяется на IPv6.
- На Windows исправлена обработка локальных уведомлений Teredo и распознавание собственной панели при запуске по короткому пути. На macOS защищаемое приложение больше не может приостановить вместе с собой системную команду, которой Zaslon проверяет сеть.

### Панель и трей

- В «Обзоре» видно, какие приложения действительно приостановлены и какой домен не удалось проверить. Если страна общего IP неизвестна, Zaslon может показать страну по результатам доменных проверок. В журнале смена причины паузы отделена от новой приостановки.
- На Windows левый щелчок по значку в трее открывает Zaslon, правый — меню. Открытое меню больше не перестраивается под курсором. Панель открывается с заголовком «Zaslon» без приглашений Edge войти в аккаунт или перевести страницу.
- В настройках можно выбрать светлую, тёмную или системную тему. У встроенных приложений появились иконки сервисов, а «Обзор» помещается в окно стандартного размера.

### Установка

- Добавлены команды установки и обновления для Windows, Linux и macOS, а также команда удаления для Windows. Установщик сохраняет настройки при обновлении. [Инструкции в README](https://github.com/avazar/zaslon/blob/dev/README.md#с-чего-начать)

## 1.3.0 - 16.11.2026

Предварительная версия Zaslon.

### Защита приложений

- В новых профилях приложения не выбраны; существующий явный выбор сохраняется. Разрешённые IP/страны и приложения включаются пользователем.
- Выбранные приложения и обнаруженные потомки остаются приостановленными до разрешённого результата проверки. Автоматическое завершение по таймеру убрано.
- При смене сети процессы сначала приостанавливаются, затем проверяется внешний IP. Устаревшие результаты не разрешают возобновление. На Windows учитываются события интерфейсов, адресов и маршрутов IPv4/IPv6.
- Для приложений добавлены отдельные доменные проверки IP. Списки доменов заполнены по умолчанию, включение проверок отделено от редактирования списка; результаты показываются таблицей в настройках приложения.
- При недоступности IP или IPv6 можно выбрать приостановку либо продолжение с предупреждением. Полученный запрещённый IP продолжает блокировать возобновление.
- После тайм-аута обязательной доменной проверки выполняется одна немедленная повторная попытка. До успешного подтверждения приложение остаётся на паузе.
- Claude Code и Codex через Node/Bun на Windows распознаются по входному скрипту, независимо от каталога установленной версии.
- Исправлены пересечения общих и отдельных правил, учёт потомков, очистка ошибок завершившихся процессов и обработка времени таймеров. Подтверждённые локальные уведомления Teredo фильтруются.

### Восстановление после сбоя

- На Linux сигналы отправляются через `pidfd` с проверкой личности после открытия дескриптора. Небезопасный переход к сигналам только по PID при недоступном API не выполняется; требуется ядро 5.3+.
- На Linux/macOS уже остановленный процесс не присваивается Zaslon и не включается в журнал восстановления. На macOS личность дополнительно сверяется перед каждым сигналом; гонка после этой сверки и конкурирующие Unix-остановки остаются ограничениями.
- Собственные операции приостановки записываются в журнал с PID и временем создания процесса.
- Повторный запуск принимает подтверждённые приостановки без предварительной разморозки. Возобновление требует свежей разрешающей проверки, включая правила приложений и потомков.
- Аварийное снятие приостановок вынесено в отдельную утилиту `zaslon-recover`. Неопределённые операции и повреждённый журнал требуют отдельного разбора.

### Панель и сборка

- Добавлены настройки недоступных проверок, раскрывающиеся настройки приложений и диагностика с доменом, конкретной ошибкой и источником сетевого события.
- На Windows/macOS повторное открытие панели активирует существующее окно. Выход или сбой основного процесса закрывает панель; закрытие самой панели оставляет защиту работающей. На Linux используется вкладка браузера.
- На Windows панель получает собственный `AppUserModelID` — `Zaslon.Panel`, иконки окна и группы на панели задач. Она группируется отдельно от Edge. Иконки выбираются с учётом масштаба Windows.
- Служебные всплывающие окна Edge исключены из поиска панели. Панель Windows использует отдельный временный профиль браузера.
- Номер `1.3.0` задаётся в файле `VERSION`. В Windows он включается в приложение, утилиту восстановления и свойства обеих EXE. Обновлены README и инструкция для локального Windows-пакета.
- В Windows CI добавлена проверка готового EXE: идентификатор, изображения иконок, повторное открытие и закрытие панели, сохранность соседнего тестового окна Edge.
- CI собирает полные Windows/Linux/macOS-пакеты с утилитой восстановления, инструкцией, лицензией, версиями и контрольными суммами. Проверяются содержимое архивов, архитектуры обеих программ, их команды версии на родной архитектуре и подпись распакованного macOS-приложения. Пакеты сохраняются как артефакты CI.
- Команды Windows GUI-приложения сохраняют перенаправление stdout/stderr, чтобы вывод версии можно было проверить автоматически.
- Добавлен PowerShell-установщик Windows: проверка полного пакета, установка без администратора, сохранение настроек, обновление с принятием приостановок и откатом файлов. Удаление отказывается продолжать при оставшихся записях восстановления.
- Добавлен общий установщик Linux/macOS без sudo: проверка SHA-256 и полного архива, команды/ярлыки, сохранение настроек и предыдущей версии, откат прерванной замены. Занятый профиль и удаление при незавершённом восстановлении отклоняются; сигналы процессам не отправляются.
- Ручной релизный workflow проверяет тег и VERSION, запускает CI трёх ОС, собирает пять архивов и установщик с закреплённой версией, формирует контрольные суммы и происхождение сборок. По умолчанию создаётся черновик предварительного выпуска.

### Проверки и ограничения

В CI пройдены нативные тесты, `go vet` и сборка Windows, Linux и macOS. Сквозные проверки готовых Windows EXE охватывают доменные ошибки, приостановку специальных процессов и потомков, аварийный перезапуск, восстановление и работу панели с Edge.

В Windows 11 VM проверены обрыв IPv4 VPN, приостановка тестового приложения с потомком, восстановление защиты после аварии без предварительной разморозки и возобновление после повторного подключения с другим IP той же разрешённой страны.

Проверки доменов используют соединения Zaslon; собственный прокси приложения и маршрутизация VPN по процессам могут давать другой выход. Приостановка процессов не гарантирует блокировку каждого пакета до обнаружения сбоя.

DNS/IPv6 при реальном обрыве VPN, сон/пробуждение, сбой питания и реальные приложения требуют отдельных испытаний. Сквозные сетевые испытания и GUI-сеанс Linux/macOS не подтверждены. Автоматическое обновление отключено; публикация выполняется вручную.
