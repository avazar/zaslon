# Проект вкладки «Проверка»

Пользователь открывает «Проверку», когда хочет понять, почему приложение остановилось, или проверить новую конфигурацию VPN. Первый экран отвечает на три вопроса: какие домены ответили, какие адреса и страны они увидели и какие выходы разрешены правилами приложений. Все примеры в макете вымышлены.

## Первый экран

Вкладка находится рядом с «Обзором». При открытии она показывает последние измерения Zaslon и время каждого результата. Сверху — вывод по текущим измерениям и кнопка «Проверить сейчас». При проблеме в сводке сразу видны приложение, домен, семейство IP и причина. Ниже — маршруты и проверка без системного прокси. Технические подробности открываются нажатием на строку со стрелкой, как в «Истории».

В строке маршрута видны домен, связанные приложения и отдельно IPv4 и IPv6. Рядом с каждым полученным адресом написана его страна. Если адрес получен без геоданных, подпись — «Страна неизвестна». Страна IPv4 и страна IPv6 берутся из соответствующих измерений. Раскрытая строка содержит время и результат по правилу каждого приложения. Для тайм-аута видны семейство адресов и причина. Для недоступной, выключенной или ещё не выполненной проверки используются разные подписи. У просроченного результата видны возраст и пометка «Устарело». При тайм-ауте в ячейке видна причина отсутствия ответа.

Общий IP служит точкой сравнения. Различие между ним и адресом сервиса само по себе допустимо при раздельной маршрутизации. Результаты получены соединениями самого Zaslon. Если у Claude или ChatGPT свой прокси, фактический выход приложения может отличаться.

## Действия и данные

Колонка «Время ответа, мс» показывает текущее и среднее время отдельно для IPv4 и IPv6. Измеряется время от начала HTTP-запроса до получения и проверки ответа сервиса. Для общего IP с несколькими источниками измеряется длительность общей проверки семейства. Среднее округляется до целых миллисекунд по успешным ответам среди последних пяти попыток этого маршрута и семейства в текущей сети. Валидный ответ с запрещённым IP тоже имеет измеренную длительность. Тайм-аут отмечается словом «тайм-аут». Пока успешных ответов нет, у среднего стоит прочерк. Смена сети или режима прокси начинает новую серию.

Под таблицей размещается раздел «Сведения об IP». Адрес выбирается из уникальных полученных IPv4 и IPv6, включая результат явно запущенной прямой проверки. По умолчанию выбран общий IPv4, если он известен. Карточка показывает справочные сведения IPQuery и дату их получения. [Описание полей API](https://ipquery.io/developers/api) и [правила классификации](https://ipquery.io/sources).

| Поле карточки | Как читать ответ IPQuery |
| --- | --- |
| Провайдер, сеть (ASN), страна | Имя провайдера из `isp.isp`, номер сети из `isp.asn`, страна по `location.country_code`. При пропуске поля — «Нет данных». |
| Тип сети | «Мобильная сеть» при `risk.is_mobile = true`, «Дата-центр» при `risk.is_datacenter = true`. При совпадении показать обе метки. При отсутствии положительных признаков — «Не определён». |
| VPN, прокси, Tor | Отдельная строка значений для `risk.is_vpn`, `risk.is_proxy` и `risk.is_tor`. Для каждого признака показать «Есть в базе», «Нет в базе» либо «Нет данных», если поле отсутствует или равно `null`. |

Сведения сохраняются локально на семь дней для каждого IP. Выбор адреса показывает сохранённый результат. Если данных нет или прошло семь дней, кнопка «Запросить сведения у IPQuery» отправляет выбранный адрес по HTTPS на `api.ipquery.io/{ip}`. Рядом с кнопкой видны адрес и получатель. При ошибке карточка показывает причину и позволяет повторить запрос. Последний успешный результат для этого адреса остаётся виден с датой и пометкой «Устарело». Метки описывают запись об адресе в базе. Решение о паузе приложения принимается по правилам защиты.

| Действие | Поведение |
| --- | --- |
| Открыть вкладку | Прочитать текущий снимок защиты. Для первой установки показать «Ещё нет измерений». Для закрытого приложения указать, почему его домены пропущены. |
| Проверить сейчас | Однократный диагностический проход через обычный маршрут Zaslon: общий выход и настроенные домены запущенных защищаемых приложений. Общий для нескольких приложений адрес проверяется один раз для каждого семейства. Вердикт рассчитывается отдельно по правилам каждого приложения. |
| Сравнить выход с прокси и без него | Отдельное действие с пояснением, что проверочный сервер может увидеть прямой IP. После подтверждения проверить одну и ту же точку и семейство адресов с системным прокси и с явным обходом прокси. При успехе показать оба IP с их странами. При ошибке показать, какая попытка не удалась. При отсутствии системного прокси сообщить об этом до запроса. Обход прокси сохраняет системную маршрутизацию, включая VPN-туннель. |

Повторный клик во время проверки присоединяется к текущей операции. При смене сети результаты незавершённого прохода отбрасываются. Статус фоновой защиты, её интервалы и решения о возобновлении принадлежат действующему механизму защиты. Диагностический запрос, в особенности прямой, не может подтвердить разрешённый маршрут для снятия паузы.

## Как встроить в Zaslon

- **Уже есть** общий IP, страна, время общего измерения, доменные результаты с отдельными ошибками и тайм-аутами IPv4/IPv6, правила приложений, определение системного прокси и диагностика DNS. За исходные данные взять снимок guard и сервисные измерения из internal/guard/domains.go. Сохранять связь общего домена со всеми приложениями.
- **Понадобится** отдельная ограниченная по времени операция диагностики в локальном API панели, с привязкой к текущей сети. Переиспользовать HTTP-транспорт и разбор ответов из internal/netwatch. Для ручного сравнения явно задать режим прокси. Отделить время начала измерения от его длительности и ошибок.
- **Следующим этапом** добавить справку о DNS и часовом поясе. Расхождение часовых поясов и репутация адреса остаются справочными. WebRTC имеет смысл проверять в выбранном пользователем браузере.

## Приёмка первой версии

1. Открытие вкладки и просмотр строк не создают сетевых запросов к проверочным сервисам. Ручной проход не меняет расписание фоновых проверок.
2. В свёрнутой строке у каждого IPv4 и IPv6 видны страна и результат проверки. Зелёная галочка означает, что IP разрешён, красный крестик — что адрес вне списка. При тайм-ауте видны янтарные часы и подпись «Тайм-аут». У каждого значка есть текст для экранного диктора. Тайм-аут IPv4 у одного домена сохраняет успешный результат IPv6. Разные разрешённые IP отображаются без тревоги.
3. Один домен двух приложений измеряется один раз. Если один и тот же IP разрешён только одному приложению, раскрытая строка показывает оба решения.
4. Прямой запрос возможен только после явного действия. Отмена и просмотр текущих маршрутов его не запускают.
5. Сводка объясняет проблему при первом запуске, даже если это первое измерение сети. При смене сети во время прохода результаты старой сети отбрасываются. На узком экране маршруты и их детали остаются доступны с клавиатуры.
6. Открытие вкладки, выбор IP, ручная проверка маршрутов и истечение срока кэша сами по себе не отправляют адрес в IPQuery. Ответ на запрос для IPv4 не заменяет карточку IPv6, выбранного во время загрузки. Тайм-аут справочного запроса сохраняет статус защиты и результаты маршрутов.
