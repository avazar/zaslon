Zaslon — предварительная сборка для Linux/macOS

Версия указана в VERSION; платформа и архитектура — в имени архива.
В комплекте приложение, независимая утилита восстановления, LICENSE,
README.txt, VERSION и SHA256SUMS.txt с суммами всех файлов пакета.

Установщик

В том же выпуске есть install.sh. Запуск: sh install.sh (без sudo).
Для локального пакета/черновика: sh install.sh --package ./ИМЯ-АРХИВА
  --checksums ./SHA256SUMS.txt --no-start
Перед обновлением закройте защищаемые приложения и выйдите из Zaslon:
установщик отказывается менять занятый профиль и не отправляет сигналы процессам.
Сохраняются настройки, журнал и предыдущие файлы в program.backup-*.
Удаление: sh install.sh --uninstall. При оставшихся приостановках оно запрещено.
Для офлайн-удаления также укажите --package и --checksums.

Linux

Распакуйте архив в постоянный каталог. Запуск: ./zaslon
Без трея: ./zaslon headless
Требуется ядро Linux 5.3 или новее с доступными pidfd_open/pidfd_send_signal.
Без этих вызовов управление процессами сообщает ошибку защиты; небезопасного
перехода на сигналы только по числовому PID нет.

Настройки: ~/.config/zaslon, если не задан ZASLON_DIR.
Установщик учитывает XDG_DATA_HOME и XDG_CONFIG_HOME; команды — ~/.local/bin.

При доступной для записи cgroup v2 Zaslon приостанавливает защищаемые процессы
по отдельности. После успешной проверки терминал остаётся у приложения.
Если делегирование недоступно, действует строгая пауза сигналами. Для Codex
и Claude Code выполните в Bash перед запуском (или добавьте в ~/.bashrc):

  source <(zaslon bash-init)

Для других консольных программ перечислите имена, например:

  source <(zaslon bash-init codex claude aider)

Затем запускайте программы по имени из этой оболочки. Список приложений и
правила защиты задаются в Zaslon отдельно. Интеграция сохраняет существующие
алиасы и функции; для запуска по абсолютному пути она не применяется.

macOS

Приложение Zaslon.app содержит обе программы и поддерживает Apple Silicon/Intel.
Утилита восстановления находится в Zaslon.app/Contents/MacOS/zaslon-recover.
Запустите Zaslon.app. Подпись ad-hoc проверяется при упаковке; Developer ID
и нотариального заверения в этой предварительной сборке нет.

Настройки: ~/Library/Application Support/Zaslon, если не задан ZASLON_DIR.
Установщик хранит файлы в подкаталоге program; приложение доступно через
~/Applications/Zaslon.app. Подпись приложения при установке не изменяется.

Первый запуск

Приложения по умолчанию не выбраны; существующие настройки сохраняются.
В панели задайте разрешённые IP/страны, затем выберите приложения.
Обычный первый запуск нового профиля включает автозапуск при входе;
это можно отключить в меню. Самообновление отключено.

После сбоя

Повторный запуск принимает подтверждённые приостановки без предварительного
возобновления. До свежей успешной проверки они сохраняются.
Аварийное возобновление — отдельное действие, прекращающее защиту.
Сначала завершите Zaslon вместе с супервизором. Для обычного Linux-профиля:

  ./zaslon-recover -dir "$HOME/.config/zaslon"
  ./zaslon-recover -dir "$HOME/.config/zaslon" -resume

Для macOS используйте путь к helper внутри Zaslon.app и каталог
"$HOME/Library/Application Support/Zaslon". Для отдельного профиля укажите
его фактический каталог. Первая команда показывает журнал, вторая возобновляет
подтверждённые операции. Неопределённые операции не повторяются вслепую.

Ограничения

Уже остановленный процесс не присваивается Zaslon и не включается в его журнал.
SIGSTOP/SIGCONT не имеют независимых счётчиков владельцев: внешняя остановка,
возникшая одновременно с нашей или после неё, не может быть надёжно отделена.
На macOS между последней проверкой личности и сигналом также остаётся гонка PID.
Эти ограничения отличаются от счётчиков приостановки Windows.

Это приостановка процессов, а не пакетный брандмауэр. Собственные прокси и
маршрутизация по процессам могут отличаться от соединений проверок Zaslon.
WSL, контейнеры и системные службы не входят в подтверждённую поддержку.
Сетевые настройки программа не меняет.
