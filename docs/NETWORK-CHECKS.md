# Проверка выхода к конкретным сервисам

## Задача

При раздельной маршрутизации сайты проверки IP и домены приложения могут идти
разными путями. Общий внешний IP не доказывает, какой адрес видит нужный сервис.
В Zaslon реализованы отдельные измерения на доменах защищаемого приложения.
Они включаются явно для каждого приложения и действуют также на его потомков.

## Включение

В разделе «Приложения» у каждой программы есть кнопка «Настройки».
В раскрытом блоке сначала выбираются общие либо собственные разрешённые IP,
подсети и страны. Эти разрешения применяются ко всем измеряемым адресам этого
приложения. При выборе собственных разрешений общий список копируется;
возврат к общим убирает переопределение, сохраняя доменные настройки.
Ниже расположен блок «IP на доменах приложения» с отдельным переключателем,
таблицей результатов и кнопкой «Редактировать домены».
Для Claude, ChatGPT, Codex и Perplexity списки заполнены заранее; для других
приложений их задают вручную. Редактор раскрывается по кнопке, поддерживает
сохранение, отмену и возврат стандартного набора. Черновик не теряется при
автоматическом обновлении результатов.

Список и включение независимы. Выключение сохраняет список и возвращает общую
проверку IP. Сохранение списка не включает режим. Нельзя включить пустой список
или стереть все адреса у включённой проверки. Настройки можно подготовить до
включения защиты приложения; без выбранной защиты запросов к его доменам нет.
Смена режима сначала приостанавливает процессы, затем требует новой проверки.

Эквивалент в `config.yaml`:

```yaml
domain_checks:
  claude: [claude.ai, api.anthropic.com]
  chatgpt: [chatgpt.com]
  codex: [chatgpt.com, api.openai.com]
  perplexity: [www.perplexity.ai]
domain_checks_enabled:
  claude: true
  chatgpt: true
  codex: true
  perplexity: false
```

Ключ — ID выбранного пресета или имя своего приложения в нижнем регистре.
Пример не добавляет приложения в `apps` и не меняет разрешения. Домены выбирайте
по фактическому способу работы; присутствие домена в готовом наборе не доказывает,
что конкретная версия приложения использует только его. Для своего API можно
задать его HTTPS-домен, если он поддерживает `/cdn-cgi/trace`. Другие пути,
авторизация в URL, query и fragment не допускаются.

В новых профилях списки заполнены, а `domain_checks_enabled` пуст: все переключатели
выключены. При чтении старого файла без `domain_checks_enabled` только прежние
непустые списки считаются включёнными. При следующем сохранении пишется явная карта
переключателей. В новом формате заполненность списка больше не включает проверки.
Проверяются только явно выбранные приложения с включённым режимом; одинаковые домены разных
приложений измеряются один раз за проверку. HTTP разрешён только для буквальных
loopback-адресов, чтобы тестировать на локальных серверах; такие запросы идут
напрямую в loopback, без системного прокси.

## Решения и срок действия

В панели «Настройки → Защита» есть независимые политики `ip_unavailable_action`
и `ipv6_unavailable_action`. Обе по умолчанию `suspend`. Явный `ignore` разрешает
работу с предупреждением при недоступном результате соответствующей проверки;
проверки при этом продолжаются. Первая политика относится также к отсутствию,
ошибке или истечению срока IPv4-результата обязательного домена. Вторая применяется
к его IPv6 отдельно. Если весь результат домена отсутствует/устарел и IPv6 возможен,
для продолжения нужны разрешающие политики для обеих недоступных семей адресов.
Это не определение отсутствия утечки и не подтверждение работы VPN.

Полученный актуальный запрещённый IPv4/IPv6, конфликт ответов, недостаточный кворум,
блокирующий DNS и ошибки контроля процессов/подписки не игнорируются этими настройками.
Противоречащие IPv6-ответы учитываются отдельно от недоступности IPv6. Работает также
пересечение политик родителей и потомков: исключение своего сбоя не обходит запрет
другого приложения. Изменение политики сначала инвалидирует результат и приостанавливает
процессы; дальнейшее решение принимается по завершении новой проверки.

- Для приложения с включёнными доменными проверками общие IP-сервисы остаются диагностикой,
  а каждый его обязательный домен проверяется по общему allow-list либо `app_rules`.
  Два разных разрешённых выхода допустимы; они не голосуют за один общий IP.
- По умолчанию недопустимый IP, HTTP 403, тайм-аут, редирект или неверный ответ удерживают только
  соответствующее приложение и потомков. Подмена ошибки успешным общим IP запрещена.
- Проверки идут каждые 15 секунд; зависшая общая диагностика не отодвигает этот срок.
  При смене сети/настроек или окончании ручной паузы старые результаты сбрасываются:
  сначала приостановка, затем свежие измерения. Результаты имеют номер проверки.
- Если обязательный IPv4/IPv6 домена не измерен из-за тайм-аута и процессы уже
  приостановлены, сразу запускается один внеочередной цикл доменных проверок.
  До его результата сохраняются ошибка и приостановки; общий IP или ответ прошлого
  запроса не разрешают возобновление. Нужны актуальные разрешённые результаты всех
  обязательных доменов и выполнение отдельных правил потомков.
  Повторная ошибка сохраняет обычный цикл 15 секунд. Дополнительная немедленная
  попытка разрешается снова после подтверждённого успеха либо инвалидации сети/настроек.
  HTTP 403, неверный формат, устаревший результат и явно игнорируемая недоступность
  сами по себе такую попытку не запускают. Тип тайм-аута передаётся из транспорта;
  поиск слова timeout в тексте ошибки не используется. В истории и логе добавляется
  `retry=immediate after domain timeout` после записи исходной причины.
- При отсутствии сетевого события предыдущий успех действует не более 30 секунд,
  чтобы следующая ограниченная по времени проверка успела завершиться. После этого
  недоступность обрабатывается выбранной политикой. При `suspend` без нового
  подтверждения процессы приостанавливаются. Ошибка нового измерения обрабатывается
  сразу по результату, даже если прежние 30 секунд ещё не истекли.
- При включённом `check_ipv6` IPv6 измеряется отдельно, если на активном интерфейсе
  он возможен. Ошибка IPv6 даёт неопределённый результат. Отсутствие AAAA в системном
  DNS без системного прокси отличается от тайм-аута. Отсутствие подходящих локальных
  IPv6-адресов остаётся ограничением консервативной проверки интерфейсов.
- Если ребёнок сам совпал с правилом другого приложения, он должен удовлетворять
  и собственным правилам, и правилам предков. Одной приостановкой владеет одна группа.
  Уже обнаруженный потомок остаётся под защитой после выхода родителя, в том числе
  если в момент выхода он работал. Обнаружение новых процессов по-прежнему опросное.
- Ручная пауза/выход освобождают собственные подтверждённые приостановки.
  Явно доверенная сеть остаётся исключением после успешной общей проверки IP;
  не добавляйте её для режима «только разрешённый выход».

Панель показывает домены, IPv4/IPv6, время измерения, ошибку и причину приостановки.
Поле общего IP не выдаётся за результат измерения конкретного домена.

## Стандартные домены

Встроенные списки используют диагностический путь `/cdn-cgi/trace`
без авторизации на доменах:

| Семейство приложений | Домены по умолчанию |
|---|---|
| ChatGPT / Codex / OpenAI API | `chatgpt.com`, `api.openai.com` |
| Claude / Claude Code / Anthropic API | `claude.ai`, `api.anthropic.com` |
| Perplexity | `www.perplexity.ai`, `api.perplexity.ai` |

Доступность и формат ответа этих адресов могут меняться. Успешная проверка
одного домена не подтверждает доступность остальных или маршрут IPv6.

## Что означает ответ

Cloudflare описывает `/cdn-cgi/` как путь, который обслуживает сама сеть Cloudflare,
и `/cdn-cgi/trace` как диагностический адрес на домене:
[документация](https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/).
Ответ показывает адрес соединения с этим доменом на границе Cloudflare. Он не
является подтверждением от API обработки запросов, привязанным к сессии приложения.

Из этого следуют ограничения:

- Собственный прокси приложения, прокси с правилами по пути URL, VPN с правилами
  по процессам или другой API base URL могут дать иной выход.
- Веб-интерфейс, API, вход в аккаунт и WebSocket-соединения могут использовать
  разные домены. Одна проверка не покрывает их автоматически.
- Связи работающих потомков с уже завершившимися предками хранятся в памяти
  текущего запуска. После перезапуска без живого предка они сами не восстанавливаются,
  если процесс не записан в журнале приостановок. Для записанных замороженных
  процессов сохраняются идентичность и правила; при подтверждённой операции они
  принимаются новым guard без предварительного resume и ждут свежего разрешения.
- Доступность диагностического адреса сегодня не означает обязательство
  ИИ-провайдера сохранять его в будущем. Отказ, антибот-защита или изменение формата
  должны давать неопределённый результат, а не разрешение работы.
- Разные разрешённые IP на разных доменах сами по себе не означают утечку.
  Проверять нужно каждый адрес по правилам соответствующего приложения.
- Разрешение страны остаётся шире разрешения IP/подсети и не доказывает наличие VPN.

## Отбор сетевых уведомлений Windows

Zaslon сохраняет немедленную приостановку при значимом или неизвестном событии.
Узкое исключение — локальные IPv6-уведомления подтверждённого Teredo: link-local
адреса, локальные multicast/link-local маршруты без следующего узла и изменения
этого интерфейса. Для исключения сначала проверяются системный тип туннеля,
его LUID и индекс, а также отсутствие внешних адресов и маршрутов в снимках ОС.
Имена адаптеров и фиксированные номера интерфейсов для выбора не используются.

Неактивный Teredo может не сообщать свой тип. Тогда первые события остаются
значимыми; метаданные перечитываются вне callback и после подтверждения допускают
фильтрацию последующего локального шума. События во время снимка не разрешают
новое исключение до повторного спокойного чтения. Подтверждённая идентичность
сохраняется при переходе интерфейса в неактивное состояние.

Внешний/неизвестный адрес или маршрут, IPv4, несовпадение идентичности и неизвестный
формат события отменяют исключение. После внешней активности этот LUID больше
не исключается до перезапуска наблюдателя. Неидентифицируемое уведомление отключает
все исключения; ошибка чтения метаданных возвращает обработку всех событий.
VPN, физические интерфейсы и остальные типы туннелей под это исключение не попадают.
Linux/macOS пока сохраняют обработку всех системных уведомлений без такого отбора.

Отфильтрованные события не отменяют действующую проверку и не запускают отдельную
паузу. В журнале сохраняются суммарное количество и последний пример:
`Network notifications filtered`. Счётчик отдельных сырых уведомлений может
быть больше количества смен состояния. Периодические проверки IP продолжаются.
Системные настройки Teredo, IPv6, VPN, маршрутов и брандмауэра не меняются.

## Диагностика пауз

История панели и `zaslon.log` сохраняют приложение, адрес проверки, семейство
IPv4/IPv6 и конкретную ошибку: например, HTTP 403, ошибку DNS или тайм-аут.
Отсутствующий или просроченный результат отмечается отдельно. Ошибки принятой
проверки записываются и при политике «Продолжать с предупреждением»; запоздавший
результат отменённой проверки не выдаётся за сбой текущей сети. При успешной
повторной проверке прежняя причина остаётся в истории и журнале.

Для сетевого события записывается источник: системное уведомление либо изменение
адресов, обнаруженное опросом интерфейсов. На Windows сохраняются имя API
уведомления, тип изменения, IPv4/IPv6, индекс интерфейса и доступные данные
адреса или маршрута (префикс и следующий узел). На Linux и macOS указываются
системный канал и тип сообщения. Это источник уведомления, а не имя программы,
изменившей сеть: такие сведения ОС этим механизмом не предоставляет.

Уведомления имеют время и последовательный номер. При объединении нескольких
уведомлений сохраняются их подробности; если серия превышает буфер из 64 записей,
пропуск явно обозначается. Если описание уведомления ещё обрабатывается,
оно помечается как недоступное: ожидание диагностики не задерживает защиту.
История панели содержит последние 50 событий;
на диске действует прежняя ротация `zaslon.log` и `zaslon.log.1` по 1 МиБ.
Ответы сайтов, заголовки и данные сессий в диагностический журнал не добавляются.
Журнал содержит домены, IP и локальные сведения о сети: учитывайте это при передаче.

## Проверки

Тесты с локальными серверами проверяют разные выходы, запрещённый домен,
тайм-аут/403/неверный ответ, редирект, IPv6, устаревшие ответы, смену правил,
срок действия и пересечение правил ребёнка и родителя. Тесты не используют
реальные ИИ-сервисы. Настоящее разветвление маршрутов VPN ещё требует стенда.
Отдельные регрессии проверяют передачу запомненных правил новым потомкам после
выхода предка, смену совпавшего приложения без повторной приостановки и отсутствие
переноса правил при повторном использовании PID с другим временем создания.

## Сквозная проверка Windows EXE

Сценарий `tools/domain-e2e/main_windows.go` использует две уникальные копии
специального приложения, их потомков и независимый контрольный процесс.
Готовые `zaslon.exe` и `zaslon-recover.exe` запускаются с отдельным профилем,
локальными HTTP-серверами, пустыми пресетами и заведомо неуспешной общей
проверкой IP. Реальные приложения не включаются в цели.

Проверяются:

- Разрешённое приложение и ребёнок работают, запрещённые приостановлены.
- Проверка через 15 секунд меняет решения местами без изменения сети или настроек.
- HTTP 403 удерживает только своё приложение и потомка.
- Потомок остаётся защищённым после выхода работавшего родителя и передаёт
  его правила своему новому дочернему процессу.
- Авария супервизора и worker сохраняет приостановки; отдельная утилита возобновляет
  все четыре приостановленных процесса и очищает журнал.
- Контрольный процесс продолжает работать. После теста все его процессы завершены;
  очистка дополнительно подтверждена независимым чтением списка процессов Windows.

Все потомки испытания ограничены Windows Job Object с завершением при закрытии;
наружный срок — 90 секунд. Отчёт `result.json`, контрольные суммы EXE,
журнал и тестовый профиль создаются в игнорируемом каталоге
`build/audit/domain-e2e-*/`. Сценарий также выполняется в Windows CI.
Воспроизведение из корня репозитория, после сборки через `scripts/Dev.ps1`:

```powershell
go build -ldflags '-H windowsgui' -o build/dev/domain-e2e.exe ./tools/domain-e2e
$test = Start-Process -FilePath (Resolve-Path build/dev/domain-e2e.exe).Path -Wait -PassThru -WindowStyle Hidden
if ($test.ExitCode -ne 0) { throw 'Domain E2E failed; inspect the new build/audit/domain-e2e-* directory.' }
```

Эта проверка не меняет DHCP, маршруты, адаптеры, прокси, DNS или брандмауэр.
Сценарий выполняется только на Windows и не воспроизводит реальный обрыв VPN
или пользовательский GUI-сеанс. Полная блокировка пакетов не заявляется.

## Восстановление защиты без предварительного возобновления

Сквозной сценарий проверяет принятие журнала после завершения supervisor и worker,
а также перезапуска только worker. Тестовые процессы, включая осиротевшего потомка
и его ребёнка, должны оставаться приостановленными до свежего разрешённого ответа.
HTTP 403 не снимает паузу даже при `ignore`. После подтверждения локальными
серверами процессы должны возобновиться без лишних счётчиков приостановки.
Аварийное `-resume` проверяется отдельно; контрольный процесс продолжает работу.

Неопределённые фазы freezing/resuming не принимаются автоматически. Существующий
исправный config.yaml и доступные записанные правила обязательны. До первого
подтверждения политики игнорирования ошибок не разрешают возобновление; явные
ручная пауза/выход по-прежнему прекращают защиту. Записанная приостановка — сведения
о собственной подтверждённой операции, а не гарантия от внешнего вмешательства.

В отдельной Windows 11 VM проверены потеря IPv4 VPN, приостановка приложения
с потомком, принятие журнала после аварии и возобновление после повторного
подключения с другим IP той же разрешённой страны. Этот прогон не подтверждает
DNS/IPv6, сон/пробуждение, сбой питания или поведение реальных приложений.
Сквозные сетевые испытания и GUI-сеанс Linux/macOS также не подтверждены.

## Согласованность общей проверки

Сбор ответов IP-сервисов ждёт завершения запросов в пределах общего тайм-аута,
даже если уже получены два совпадения. Противоречащий ответ
внутри этого окна учитывается для IPv4 и IPv6. Отмена всей проверки отбрасывает
частичные успехи. Не ответивший сервис не голосует; узнать его потенциальный
ответ невозможно. Это устраняет преждевременное принятие кворума, но не заменяет
отдельные проверки доменов при раздельной маршрутизации.
